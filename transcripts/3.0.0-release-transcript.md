**What lerna was doing, and what replaced it**

Lerna wasn't needed for monorepo support itself. The repo used three of its features, and since npm 7 npm has its own **workspaces** that cover them:

| Lerna, as this repo used it | Replaced by |
|---|---|
| `lerna bootstrap`: install every package's dependencies and symlink the local packages into each other, e.g. standalone → `@imerss/inat-components` | `"workspaces": [...]` in the root `package.json`. A single `npm install` installs everything and creates the links: `node_modules/@imerss/inat-components → packages/inat-components`, and likewise for standalone and utils. |
| `lerna run build`: run `build` in each package | `npm run build -w @imerss/inat-components && npm run build -w @imerss/inat-components-utils`, the root's `buildAll` |
| `lerna exec --parallel … yarn watch`: watch several packages at once | `npm-run-all --parallel watchComponents watchUtils`, each running `npm run watch -w <package>`. `npm-run-all` was already a dependency. |

One difference: `lerna run` works out the build order from the packages' dependencies, while `buildAll` names the order outright. That doesn't matter here. Utils doesn't depend on the component, and the component's own `build` script already builds the standalone after itself, as before.

Lerna's versioning and publishing features (`lerna version` / `lerna publish`) were never used. `lerna.json` had a fixed `"version": "1.0.0"` while the packages carry their own versions, and `PUBLISH.md` describes publishing by hand. So nothing that was in use was lost. If you'd prefer lerna for those release features, current lerna versions work on top of npm workspaces and can be added back.
